## 1 作品概述

### 1.1 定位

> **维普管「交上去之后合不合规」，本作品管「写出来之前卡在哪、能不能过答辩」。**

这不是一句宣传语，是划边界。学校的论文管理系统已经解决了抄袭检测、格式审查、流程流转，而且有学校采购渠道——在那条赛道上做一个"更好的维普"没有胜算，也没有意义。

本作品选的是另一段时间：**学生从开题写到定稿的这几个月，以及走上答辩台的那十分钟。** 这段时间里真正的问题不是"格式对不对"，而是：

- 学生卡在同一个地方反复问，没人记得他问过几次；
- 导师每次都要从头解释同一件事；
- 论文写完看不出毛病，答辩被问住才发现哪都没想清楚。

### 1.2 用户与场景

| 角色 | 痛点 | 本系统提供 |
|---|---|---|
| 学生 | 同一个疑惑反复出现，不知道自己是"问一下"还是"一直没懂" | 答疑沉淀 + 问题画像 + 答辩预演 |
| 导师 | 重复回答同类问题，时间被切碎 | AI 起草草稿，导师只做审核与修正 |
| 双方 | 论文看起来完整，实际经不起追问 | 规则诊断 + 要点覆盖自查 |

### 1.3 与既有系统的边界

| | 维普类合规系统 | 本作品 |
|---|---|---|
| 输入数据 | 论文成品 | 论文 + **学生的答疑史** |
| 介入时点 | 提交之后 | 写作过程 + 答辩之前 |
| 输出 | 合规报告（查重率、格式项） | 诊断清单 + 答辩预演题单 |
| 判断依据 | 比对库 + 格式规范 | 规则 + 学生自己的困惑记录 |
| 不做什么 | —— | 不查重、不代写、不管流程 |

一句话：**本作品的价值不在"多检测出一类错误"，在"用别人拿不到的数据做出别人做不出的判断"。** 那份数据就是答疑史。

### 1.4 数据流

```
学生提问 ──→ AI 起草草稿 ──→ 导师审核修正 ──→ 入库沉淀
                                                  │
                                                  ↓
                                        主题风险画像（确定性）
                                                  │
                                                  ↓
                                        答辩预演题单（确定性）
                                                  │
                                    学生作答 ──→ 要点覆盖判分
                                                  │
                                                  ↓
                                        发现缺口 → 带着新问题回去问
```

这条线是**一条链，不是四个并列功能**：上一层的产出是下一层的输入。

|---|---|---|---|

| ② 写作台（诊断） | `pages/2_写作台.py` | 已建成 | 四类规则检查，确定性，不调模型 |

### 2.2 代码结构与依赖方向

```
app.py                      总览：三层状态 + 数据来源与清空
pages/                      四个页面，只做展示与交互
core/schemas.py             数据模型（DocProfile / Section / Issue），不含逻辑
core/parser.py              docx → 章节树 + 元信息
core/checker.py             四类规则检查，纯函数
core/qa_store.py            答疑存储 + 重复检测 + meta 标记
core/qa_seed.py             示例数据（4 条学生线，幂等）
core/rehearsal.py           风险画像 / 题库 / 出题 / 判分，纯函数
core/rehearsal_store.py     预演记录存储，重答留痕
core/bootstrap.py           启动自愈：空库自动载入、清空防回灌
core/ai_client.py           模型封装，唯一允许出现 API 调用的地方
tests/                      58 条回归测试
```

**依赖方向单向：`app / pages → core`，core 内部不反向依赖界面。**

这条约束不是洁癖。它让 `core` 里的每一条规则都能在无界面、无网络、无密钥的环境下被测试——`pytest` 里 58 条测试没有一条需要启动 Streamlit。

### 2.3 存储设计

两个 SQLite 文件，克隆下来直接可跑，不需要装数据库服务。

**答疑表 `qa`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `student` | TEXT | 学生名，**刻意不做用户体系** |
| `stage` | TEXT | 开题 / 中期 / 定稿 |
| `question` | TEXT | 学生原话 |
| `ai_draft` | TEXT | AI 起草的草稿 |
| `answer` | TEXT | 导师修订后的答复（为空则回落到草稿） |
| `status` | TEXT | 待审核 / 已通过 / 已退回 |
| `tags` | TEXT | 主题标签，出题依据 |
| `reviewer_note` | TEXT | 审核备注 |
| `created_at` / `reviewed_at` | TEXT | 时间戳 |

**预演表 `rehearsal`**

| 字段 | 说明 |
|---|---|
| `question` / `answer` | 题目与学生作答 |
| `hit` / `total` | 命中要点数 / 要点总数 |
| `level` | 未作答 / 有缺口 / 基本 / 扎实 |
| `missing` | 漏掉的要点名，直接展示给学生 |
| `source_ids` | 这道题来自哪几条答疑记录，可追溯 |
| `ai_note` | AI 评委追问（标注为参考） |

**元信息表 `meta`**：只存键值对，目前两个键——`demo=1`（本库是示例数据）、`demo_off=1`（用户主动清空过）。

**为什么扁平到底、不做用户体系：** 这一阶段的真实目标是「把闭环跑通并演示清楚」，不是「上线给一个学院用」。提前拆用户表、权限表、角色表，只会把两周能完成的事拖成两个月，还引入一堆无法验证的分支。**等真的要多角色登录了再拆——现在拆就是给自己挖坑。**

### 2.4 启动自愈（`core/bootstrap.py`）

这一层解决两个真实问题，不是演示技巧：

1. **首次访问。** `qa.db` 含学生提问，不能进公开仓库。于是评委 clone 下来、或云端容器重启后，库是空的——主打功能变成一句「还没有答疑记录」。启动时若库为空，自动载入 30 条示例并打 `meta.demo` 标记，页面顶部标明「示例数据（虚构学生，非真实访谈）」。
2. **能清空、且不许自己长回来。** 用户点过「清空」就写 `demo_off` 开关，之后不再自动载入。**清空按钮按下去、刷新又满了，等于当众承认 bug。**

安全约束：`is_demo()` 判定为示例数据才允许清空，否则抛异常。判定优先看 `meta` 标记，老库退回「所有学生名 ⊆ 示例名单」。真实数据不允许被一键抹掉——判错的后果只是多显示一行说明，判不出来的后果是删掉别人的东西，两者不对等。

## 3 关键实现

### 3.1 文档解析（`core/parser.py`）

把 docx 的段落流切成章节树。难点全在**标题误判**：Word 转来的文档里，`3.1 引言` 和正文里的 `3.1 是什么意思` 长得几乎一样。

三重限制同时成立才算标题：

1. 长度不超过 40 字；
2. 不以句末标点结尾（标题不会是完整句子）；
3. 必须以章节编号开头，编号后还有 ≥2 字标题文字，且不以 `、）．` 起头。

### 3.2 四类规则检查（`core/checker.py`）

全部是确定性判断，同一份文档永远得到同一份清单。

| 检查 | 判据 | 阈值 / 特殊情况 | 防误报措施 |
|---|---|---|---|
| 引用双向核对 | 文献表编号集合 ↔ 正文引用编号集合，**两个方向都查** | 支持 `[1]` `[1,2]` `[1-3]` `[1，2]` | 编号从 1 起；`[0,…]` 判为数学区间整段丢弃；区间展开限 `b-a<50` |
| 图表悬空 | 正文提及「图 x-y」「表 x-y」↔ 图注/表注集合 | 全文图数或表数为 0 时直接判严重 | 图注须独立成段且以「图 x-y」开头 |
| 结构失衡 | 空章节、过短章节、小结比重 | 过短阈值 300 字；小结 > 最长正文节 × 1.2 | 有子节的父节正文为空属正常，跳过 |
| 标题承诺未兑现 | 标题含「表结构/数据表/表设计/数据库表/字段说明」且全文表格数 0 | 全文有表则整条跳过 | —— |

**只查一个方向等于睁一只眼。** 正向查「列了没引用」（凑数嫌疑），反向查「引用了不存在」（编号错乱或编造）。两个方向都是答辩现场会被直接追问的问题。这一条是导师反馈里点名要的方向。

**真实样本上的迭代记录（工程诚实）：** 早期版本的正则在智能温室那篇论文上误报——正文写「归一化到 [0,1] 区间」，被当成引用了第 0 条文献。加了两条防御（编号从 1 起、`[0,…]` 整段丢弃）并补了回归测试。误报比漏报更伤信任：**学生会因为一条假问题否定整份清单。**

样本实测：

| 样本 | 字数 | 章节 | 问题 | 严重 |
|---|---|---|---|---|
| 第三章 智能温室…感知层设计与数据预处理 | 3,369 | 6 | 6 | 3 |
| 第三章 系统总体设计与数据库设计 | 4,002 | 9 | 7 | 4 |

### 3.3 重复问题检测：为什么不用 Jaccard

学生提交新问题时，边输入边比对历史记录，命中就提示「这个问题历史上问过 N 次」。

实现是**字符 bigram 的重叠系数**：

```
score = |bigram(A) ∩ bigram(B)| / min(|bigram(A)|, |bigram(B)|)
阈值 0.3
```

不用 Jaccard（交集/并集）的原因很具体：**学生追问时往往只说半句**——「那数据量不够怎么办」。两个句子长度差一大截，并集会把它稀释到很低，Jaccard 认不出来；重叠系数除以较短集合，还能正确识别。

这个检测**不调模型**。导师最想要的第一件事是「这个问题我答过」，而判断"答过没"本来就该是确定性的、瞬时的、不要钱的。

实测：`我的数据只有200条，做回归够吗？` → 命中 `样本量只有300条，做回归够吗？`（62%）；`答辩PPT大概要多少页` → 命中历史同类问题（57%）。

### 3.4 主题风险画像：权重是拍出来的，但方向有依据

答疑记录按标签汇总，算出每个主题的风险分：

```
风险 = 提问次数 × 1.0 + (涉及时段数 − 1) × 1.5 + 未答复条数 × 1.2

高：≥ 5.0　　中：≥ 3.0　　低：< 3.0
```

权重是经验值，但**每一项都对应一个可观察的事实**：

- **次数**：问得多就是卡得久；
- **跨阶段（权重最高）**：从开题一路问到定稿，说明中间那几次答复没真正解决问题。这比"问了几次"更能说明问题性质；
- **未答复**：导师还没回答的问题，答辩时必然裸奔。

以示例数据「陈同学」为例：数据来源主题被问 4 次、横跨开题/中期/定稿三个阶段、0 条未答复 → 得分 7.0，判为高风险，题单前两题都落在它上面。

**为什么不用语义聚类：** 标签是学生提问时顺手打的，稳定、可解释、导师一眼能认。语义聚类会给出"这两个问题距离 0.83"这种没人能反驳也没人能验证的结论，出了问题无法定位。

### 3.5 出题引擎（`core/rehearsal.py`）

**题库结构：** 14 个主题 / 17 道题 + 3 道通用必答题（"做了什么 / 创新点 / 不足"）= 20 道。每题包含：

- 3 个 **考察要点**（名称 + 关键词集合）；
- 1 条 **可能的追问**；
- 1 句 **评委为什么问这个**（学生怕的不是问题本身，是不知道对方在探什么）。

**三条硬约束：**

1. **一个主题最多出 2 题。** 同一主题连出三道意义不大，还挤掉别的考点。
2. **题库里没有的主题直接跳过，不硬凑。** 凑出来的题学生一眼能看出来。
3. **凑不满用通用必答题补齐**，仍不满就短着——宁可给 4 道真题，不给 6 道掺水的。

**每题可溯源：** 题单里的每道题都带 `source_ids`，指向触发它的答疑记录编号。这是「用你自己的困惑出题」唯一的证据，也是答辩时敢当场换学生演示的前提。

**默认打开谁：** 按「该生最高主题风险分」排序，不是按姓名字典序。原先按姓名排，最该练的学生排在最后，演示第一屏落在风险最低的人身上——**那是排序错了，不是巧合。**

### 3.6 要点覆盖判分：为什么只报命中数、不打分

```
命中率 ≥ 0.8 → 扎实
命中率 ≥ 0.5 → 基本
命中率 < 0.5 → 有缺口
空答        → 未作答（不是 0 分）
```

三个刻意的决定：

1. **不给百分制。** 78 分是假的精确，学生只会盯着分数。告诉他「你漏了『说清数据边界』」，他才知道下一版改哪。
2. **「未作答」和「有缺口」分开。** 没答和答错是两回事，混在一起会让学生误以为已经在准备了。
3. **答题前不显示考察要点。** 显示了就是给答案，预演就没有意义。要点折叠在「查看考察要点」里，并写明这个理由。

**判分是保守下限，不是真理。** 关键词匹配换个说法就会漏判。实测：学生答「数据来自公开数据集，但和我的传感器对不上」——命中 1/3，漏掉「说清数据边界」「对不齐怎么处理」。这个漏判其实是对的（他说了问题，没说怎么处理），但也说明同义表述会漏。所以界面底部固定写明：**「这里给的是自查清单，不是成绩单，导师可人工修正。」**

### 3.7 预演记录：为什么允许重答、不覆盖

每次提交都插入新记录，不设唯一约束。

答辩前的改进过程本身就是证据。单题轨迹 `1/3 → 3/3` 比「最终得分」更有说服力，也正好是答辩材料里能用的东西。界面上「逐题轨迹」一栏专门画这条线；如果答了几次都没进步，会提示「多半是漏的那条要点还没想明白，不是表达问题」。

## 4 AI 使用设计

### 4.1 一条原则：AI 只起草，不裁决

**AI 产出一律标「待审核」，导师点通过才入库。** 这条不靠自觉，靠设计锁死：

- 数据层：`answer`（导师答案）为空时 `final_answer` 才回落到 `ai_draft`；导师填了就以导师为准。
- 测试层：`test_reviewer_answer_overrides_ai_draft` 专门断言「导师改过的答案必须盖过 AI 草稿」。

学术判断不交给模型。这不是保守，是**代价对称性**：模型答错一句，代价由学生的答辩承担，不由模型承担。

### 4.2 两个调用点

全项目**只有两处**真正调用模型，都写在 `prompts/` 下归档。

**(1) 答疑起草** —— `pages/1_答疑台.py`

```
你是高校毕业论文指导助手，为导师起草答复草稿，不替导师做决定。

要求：
1. 直接回答学生的问题，不扩展到无关内容
2. 给可执行的具体建议，禁止「加强研究」「多读文献」这类空话
3. 涉及研究设计、数据可得性、结论可靠性的判断，明确写「这一点需要导师确认」
4. 200 字以内
5. 不代写论文正文，只给方向和方法
```

**(2) 答辩评委追问** —— `pages/3_预演台.py`

```
你是答辩现场的评委，正在听这名学生回答你提的问题。

规则：
1. 只针对他回答里空泛、前后不一致、没交代清楚的地方追问
2. 输出 2 条追问，每条不超过 40 字，用「1. 」「2. 」开头
3. 如果他确实答得完整，只输出四个字：暂无可追问
4. 不评价他答得好不好。评委不打分，只继续问
5. 不要复述他的答案，不要给建议
```

第 3 条是**给模型一个不追问的出口**。不给出路，它会为了凑满两条而硬编问题，那种编出来的追问学生立刻能识破——一旦识破，整个预演的可信度就没了。第 4 条不加，输出必然滑向「回答得比较完整，但可以更具体」这种泛泛点评；学生缺的不是鼓励，是下一个问题。

### 4.3 工程约束（`core/ai_client.py`）

| 约束 | 做法 | 为什么 |
|---|---|---|
| 换供应商不改代码 | 只认 `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` | 默认 DeepSeek，可切任意 OpenAI 兼容接口 |
| 密钥不进日志、不进页面 | 展示一律脱敏（`sk-6****ed0a · 共 35 位`） | 演示时投屏、截图都不会漏 |
| 配置状态分四态 | `missing / placeholder / invalid / ok` | 「没读到」「读到但还是模板原文」「格式不像密钥」的处理办法完全不同，混成一句会让人白折腾 |
| 异常不裸抛 | 401 / 402 / 404 / 429 / 超时 分类成中文原因 | 401 和 402 在界面上都是"调用失败"，但一个要换密钥、一个要充值 |
| 页面不白屏 | 所有调用返回 `(ok, text)`，失败时 text 就是给人看的原因 | 上层不必写 try/except |

### 4.4 实测记录（2026-10-24）

**连通性**：`ping()` 发 8 token，返回 `模型已回话：收到，请问需要我做什么？`——密钥有效、余额正常。

**起草实测**（陈同学 · 定稿 · 「结论部分怎么写得不像凑字数？」），输出 134 字：

> 结论只回答引言提出的问题，逐条对应，不重复正文。写法：每条结论用"本文发现……"开头，后接证据（数据、案例编号），再写适用范围与限制。删掉"综上所述""具有重要意义"等套话。若某条结论无数据支撑，删去或改为"待进一步验证"。结论是否成立、能否定稿，这一点需要导师确认。

Prompt 里三条硬约束都守住了：可执行、无套话、带「需要导师确认」。

**追问实测**（数据来源题，学生答「数据来自公开数据集，但和我的传感器对不上，所以只保留了能对上的字段」）：

> 1. 公开数据集具体是哪个名称、哪个版本，如何核查？
> 2. 对不上的字段占多少比例，只保留能对上的字段会带来什么偏差？

不评价、不复述、不建议——正是设计要的行为。追问会落库并标注「AI 生成，仅供参考」，导师可覆盖。

### 4.5 AI 明确不做的三件事

1. **不生成参考答案。** 答辩没有标准答案，只有"你的答案站不站得住"。模型一旦生成标准答案，学生就会背它，反而失去自己的判断。
2. **不给论文打分。** 六维评分这类功能听着唬人，但分数不可验证，学生只会为分数辩护而不是为内容改进。
3. **不做语义判定的最终结论。** 规则能判的（引用对不对、章节平不平衡、要点提没提到）全部用纯函数，可复现、不花钱、出错能定位。

**判断能不能交给模型，取决于答错的代价谁承担。** 这一条是整套 AI 使用设计的边界。

## 5 工程质量

### 5.1 测试

58 条，`pytest` 跑完 1.6 秒，全部使用临时数据库，不碰演示数据。

| 文件 | 条数 | 断言的是什么 |
|---|---|---|
| `test_checker.py` | 15 | 四类规则必须检出、误报必须不检出（含 `[0,1]` 数学区间回归） |

| `test_bootstrap.py` | 11 | 空库自动载入、清空不回流、真实数据拒删 |

**测试断言的是设计承诺，不是实现细节。** 例如：

- `test_reviewer_answer_overrides_ai_draft` —— 导师答案必须盖过 AI 草稿；
- `test_cross_stage_outranks_single_mention` —— 跨阶段重复的风险必须高于同阶段重复；
- `test_draft_is_traceable_to_records` —— 题单必须能追回答疑记录 id；
- `test_grade_empty_is_not_zero_score` —— 空答不能算 0 分；
- `cleared_db_does_not_auto_refill` —— 清空之后不许自己长回来。

这些是"如果破了，产品逻辑就塌了"的点，不是"这个函数应该返回 3"。

### 5.2 可复现性

- 报告里的每个数字都来自代码运行，不是手写文案（首页的"样本检出问题数"是启动时真跑一遍两份 docx 得出的）。

## 6 边界与局限

这一节不比前面短，因为**评委问倒一个作品最容易的地方就是这里，与其被问出来，不如自己写清楚。**

| 局限 | 具体表现 | 缓解 / 计划 |
|---|---|---|
| 要点判分是关键词匹配 | 同义表述会漏判，判分只是下限 | 界面固定写明「自查清单，非成绩单，导师可修正」；计划引入一次模型复核（仅作建议，仍是待审核） |
| 云端 SQLite 是临时的 | Streamlit Cloud 容器重启丢库 | 启动自愈让库自己长回来；文档明确标注「生产环境需换持久化存储」 |
| 示例数据是模拟的 | 4 条虚构学生线，非真实访谈 | 页面与文档全部标明；不伪装成真实采集 |
| 题库硬编码在代码里 | 20 道题写在 `core/rehearsal.py`，换到完全不同的学科要改代码 | **"换选题成本 1 天"这条原则目前不成立**，需先把题库外置成 JSON（已列入后续工作） |
| 无用户体系 | 学生名是一个字符串，没有登录、权限、隔离 | 这一阶段刻意不做，见 2.3 |
| 无版本对比 | 只能看单份文档，"改没改好"要人工对照 | 计划做两版 docx 的差异清单 |
| 规则只覆盖 4 类 | 论证是否成立、逻辑是否自洽这类语义问题没做 | 明确划为"语义层"，不在当前承诺范围内 |
| 不测表达 | 预演只看内容要点，不看语速、台风、PPT | 有意为之：内容想不清，讲得再流利也没用 |

## 7 创新点

1. **用答疑史出题。** 通用题库谁都能做，"这个学生在这个主题上问了 4 次、跨 3 个阶段"只有沉淀了过程的系统才有。出题依据可溯源到具体记录，敢在评委会现场换人演示。
2. **只报要点覆盖，不打分。** 反过来放弃"六维评分"这种看起来更唬人的功能，因为它不可验证，会诱导学生为分数辩护。
3. **AI 的边界写在代码里，不写在文档里。** 只起草、只追问、落库标待审核、导师答案优先——每一条都有对应测试。
4. **确定性优先的架构。** 能算的不用模型，所以换个人当场能跑、结果可复现、出错能定位。这是"答辩能演示"和"只能录视频"的区别。

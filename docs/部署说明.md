## 2 建应用

1. 打开 https://share.streamlit.io ，用 GitHub 账号登录
2. `Create app` → `Deploy a public app from GitHub`
3. 填：
   - Repository：`rain1ly/thesis-bench`
   - Branch：`main`
   - Main file path：`app.py`
   - App URL：可以自定义子域名，建议 `thesis-bench`
4. Advanced settings → Python version：选 **3.12**（比本地 3.13 保守一档）
5. 点 Deploy

首次构建 2–5 分钟。日志里如果出现 `ModuleNotFoundError`，看第 5 节。

## 3 配密钥

构建完成后：

**有两条入口，随便走哪条**（2026-10 核对过官方文档）：

**A. 从应用列表进（推荐）**
1. https://share.streamlit.io，确认已登录（必须是部署这个 app 的 GitHub 账号）
2. **My apps** 列表里找到 app 卡片，点右侧 **⋮（more_vert）**
3. 点 **Settings** → 弹窗切到 **Secrets** 标签页
4. 粘贴下面三行 → **Save**

**B. 从运行中的应用进**
1. 打开 app URL（`https://xxx.streamlit.app`）
2. **右下角** 点 **Manage app**（首次是展开的日志面板）
3. 面板**右上角** **⋮** → **Settings** → **Secrets**

```toml
OPENAI_API_KEY = "sk-你的密钥"
OPENAI_BASE_URL = "https://api.deepseek.com/v1"
OPENAI_MODEL = "deepseek-chat"
```

保存后应用会自动重启（约 30 秒）。

**找不到入口时的排查顺序：**

| 现象 | 原因 | 处理 |
|---|---|---|
| 列表里没有 ⋮ | 登录态掉了，或不是部署时的账号 | 退出重登，核对头像与仓库 owner 一致 |
| 有卡片但没 Settings | 应用还在构建或构建失败 | 先看构建日志，绿灯后再进 |
| 打开 app 右下角没有 Manage app | 不是以所有者身份访问（无痕窗口 / 别人发的链接） | 登录后再开一次 app URL |
| 只看到 General | Secrets 是弹窗里另一个 tab | 在弹窗顶部切换标签页 |

> **配不上也不影响演示。** 代码对密钥做了四态降级：未配置时规则检查、出题、判分、
> 老师端全部正常，只有 AI 起草与 AI 追问两处降级。但省赛那 2 分钟 AI 实拍依赖它，所以还是要配。
>
> **绝对不要把密钥写进 `app.py`。** 仓库是公开的，写进去等于公开密钥，
> 且 Git 历史里删不干净，必须走 Secrets。

> 这里必须用 **Secrets**，不能用 `.env`。`.env` 被 `.gitignore` 忽略，云端根本读不到。
> 代码里的优先级是 `Streamlit Secrets > .env / 环境变量`，所以两边都配也不会冲突。

本地想用同样的方式测试，可以建 `.streamlit/secrets.toml`（同样被忽略，不会提交），
格式照抄 `.streamlit/secrets.toml.example`。

## 5 故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 构建失败 `ModuleNotFoundError` | requirements 漏了包 | 本地 `pip freeze` 对一遍，补进 `requirements.txt` 再推 |
| 页面能开，但 AI 按钮灰色的 / 提示"密钥未配置" | Secrets 没保存，或键名拼错 | 键名必须是 `OPENAI_API_KEY`，不是 `API_KEY` / `DEEPSEEK_KEY` |
| 连通性测试返回「余额不足（402）」 | DeepSeek 账户余额用完 | 充值 10 元起；这是新账号最常见的问题，不是代码问题 |
| 连通性测试返回「密钥无效（401）」 | 密钥复制不全或已吊销 | 重新生成，粘贴时注意别漏末尾字符 |
| 连通性测试超时 | 云端访问 api.deepseek.com 慢 | 重试一次；持续失败就换 `OPENAI_BASE_URL` 到智谱 `https://open.bigmodel.cn/api/paas/v4` + `glm-4-flash` |
| 答疑记录变成 0 条 | 容器重启，SQLite 被重置 | **正常现象**，刷新一次首页会自动重新载入示例数据 |
| 首次打开要等十几秒 | 免费版闲置后会休眠 | 演示前 2 分钟先打开一次，把容器唤醒 |
| 中文显示成方框 | 浏览器字体问题 | 与部署无关，换 Chrome / Edge 即可 |

## 6 已知行为（不是 bug，不用修）

1. **容器重启后数据重置。** Streamlit Cloud 的文件系统是临时的，`qa.db` 重启即丢。
   启动自愈会让示例数据自动长回来，但**演示期间手动提交的预演记录会消失**。
   → 对策：演示走一遍完整的，别分两次做；或者在文档里如实标注"生产环境需换持久化存储"。
   诚实标注边界是加分项，假装没有才是减分项。

2. **示例数据是虚构的。** 4 条学生线（数据焦虑 / 图表规范 / 实验设计 / 问卷方法），
   页面和文档都写明了。不要试图把它说成真实采集。

3. **首页写作台那个「13 项问题」是启动时现算的。** 每次冷启动会重新跑一遍两份样本，
   约 0.2 秒，属于正常开销。

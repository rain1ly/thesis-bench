# 论文工坊 · ThesisBench

**在论文交给导师、走上答辩台之前，按导师和评委的标准先挑一遍毛病。**

学位论文预评审平台　·　2026 第九届传智杯 AI 创新应用挑战赛（个人赛 · B 组）

---

## 它解决什么问题

学生写完一万多字，自己读几遍也看不出问题；导师时间有限，往往只粗看一遍；到答辩时被问住。

问题不在写作能力，在于**自己写的东西自己看不出毛病**，而且**没人记得你一路卡在哪**。

学校已有维普那类系统，管的是「交上去之后合不合规」——查重、格式、流程。
本项目管的是「**写出来之前卡在哪、能不能过答辩**」，两者不重叠：

| | 维普类 | 论文工坊 |
|---|---|---|
| 数据 | 论文成品 | 论文 + 学生的答疑史 |
| 时点 | 提交之后 | 写作过程 + 答辩之前 |
| 输出 | 合规报告 | 诊断清单 + 答辩预演题 |

不做三件事：不查重、不代写、不管流程。

## 三层骨架（一条链，不是并列功能）

```
① 答疑台 ──→ ② 诊断台 ──→ ③ 预演台
学生问 / AI 起草    双向引用、结构硬伤    用他自己的困惑出题
导师审核入库        确定性规则检查        要点覆盖判分
      │                                      │
      └────────── 答疑史沉淀 ────────────────┘
```

**核心取舍：AI 只起草，不裁决。** AI 产出（答复草稿、评委追问）一律标「待审核 / 仅供参考」，
导师点通过才入库。学术判断不交给模型，这一点在设计上锁死，不靠自觉。

## 当前进度

| 层 | 工作台 | 状态 | 说明 |
|---|---|---|---|
| ① | 答疑台 | **可用** | 提问 → AI 起草 → 导师审核 → 沉淀；重复问题检测 + 学生画像 |
| ② | 写作台（诊断） | **可用** | 规则检查：文献双向引用、图表悬空、章节结构、标题承诺 |
| ③ | 预演台 | **可用** | 答疑史 → 主题风险画像 → 题单 → 要点覆盖判分；AI 只做评委追问 |
| — | 风险看板 | 规划中 | 需要多份材料入库 |

出题与判分**不调模型**：换一个学生当场也能出题，结果可复现。
优先级是规则先跑通，语义判断后叠——不是所有环节都值得用 AI。


## 快速开始

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt

streamlit run app.py
```

浏览器打开 `http://localhost:8501`。

第一次打开时答疑库会自动载入 30 条示例数据（虚构学生，页面会标明来源），
所以不用先做任何准备工作就能看到完整流程。清空入口在首页。

## 目录结构

```
app.py                      总览：三层链条状态 + 闭环说明 + 数据来源与清空
pages/1_答疑台.py            ① 答疑：学生提问 / 导师审核 / 记录与画像
pages/2_写作台.py            ② 诊断：上传 docx → 问题清单 → 章节字数分布
pages/3_预演台.py            ③ 预演：风险画像 / 出题 / 作答自评 / 复盘轨迹
pages/9_环境自检.py          密钥四态诊断与连通性测试
core/schemas.py             数据模型，不含逻辑
core/parser.py              docx → 章节树 + 元信息
core/checker.py             ② 规则检查，确定性，不调模型
core/qa_store.py            答疑 SQLite 存储 + 重复问题检测（bigram 重叠系数）+ meta 标记
core/qa_seed.py             30 条模拟答疑（4 条学生线，幂等载入）
core/rehearsal.py           ③ 风险画像 / 题库 / 出题 / 要点覆盖判分，纯确定性
core/rehearsal_store.py     预演记录 SQLite 存储，重答留痕
core/bootstrap.py           启动自愈：空库自动载入示例，并保证清空后不会自己长回来
core/ai_client.py           模型封装：三变量配置、错误分类、密钥脱敏
data/samples/               测试样本
tests/                      58 条回归测试
```

依赖方向单向：`app / pages → core`，core 内部不反向依赖界面。

## 两个工程上的取舍

**空库自动长出来。** `qa.db` 不进仓库（含学生提问，不能公开）。评委 clone 下来
或云端容器重启后库是空的，主打功能就成了空页面。所以启动时自动载入示例，
并打 `meta.demo` 标记 —— 标出来源，才能既诚实又能安全清空。

**清空之后不许自己长回来。** 用户点过「清空」就写 `demo_off` 开关，之后不再自动载入。
清空按钮按下去刷新又回来，等于当众承认 bug。

## 检查项

| 类别 | 检查内容 |
|---|---|
| 引用 | 参考文献列了但正文未引用；部分条目未被引用 |
| 图表 | 正文引用图/表，但文档中没有对应图片、表格或图注 |
| 结构 | 空章节、篇幅过短、小结篇幅超过正文 |
| 标题承诺 | 标题声称给出表结构，但全文没有表格 |

全部基于规则，同一份文档永远得到同一份清单。

## 运行测试


测试用 `data/samples/` 的两份真实样本做回归，断言的是「必须检出的那几类问题」，不是精确条数。

# 预演台 · 评委追问 Prompt

**位置**：`pages/4_预演台.py` → `SYSTEM_FOLLOWUP`
**参数**：`temperature=0.4`、`max_tokens=300`
**触发**：学生提交作答后**手动**点击「让 AI 评委追问」；产出经 `attach_ai_note()` 落库，标注「AI 生成，仅供参考」
**前置**：只有规则判分完成（`hit/total` 已算出）之后才允许追问

---

## System Prompt（全文）

```
你是答辩现场的评委，正在听这名学生回答你提的问题。

规则：
1. 只针对他回答里空泛、前后不一致、没交代清楚的地方追问
2. 输出 2 条追问，每条不超过 40 字，用「1. 」「2. 」开头
3. 如果他确实答得完整，只输出四个字：暂无可追问
4. 不评价他答得好不好。评委不打分，只继续问
5. 不要复述他的答案，不要给建议
```

## 用户消息模板

```
我问的问题：{question}
我原本期待他答到这几点：{points}      ← 题库里写死的 3 个要点名
他的回答：{answer}
```

**注意把"期待要点"喂进去**：不给要点，模型只能凭"回答得完不完整"泛泛判断；
给了要点，它就能精确地追问"你漏掉的那一点怎么解释"。这一步是把"通用挑刺"变成"针对这道题挑刺"的关键。

---

## 五条约束的来历

| # | 约束 | 不加会怎样 | 类型 |
|---|---|---|---|
| 1 | 只针对空泛、矛盾、未交代处 | 模型会追问细枝末节（"你的样本具体是哪天的"），评委不会这么问 | 设计预判 |
| 2 | 2 条、每条 ≤40 字 | 不限条数会输出 5–6 条，学生看不过来；不限字数会写成小作文 | 设计预判 |
| 3 | 答得完整时只输出「暂无可追问」 | **这是最重要的一条**。不给出路，模型为了凑满 2 条会硬编问题。硬编的追问学生一眼识破，整套预演的可信度就没了 | 设计预判 + 实测确认 |
| 4 | 不评价，只继续问 | 不加这条，输出必然滑向「回答得比较完整，但可以更具体」这类泛泛点评。学生缺的不是鼓励，是下一个问题 | 设计预判 + 实测确认 |
| 5 | 不复述答案、不给建议 | 复述让追问显得长，信息量为零；给建议则越界成了导师 | 设计预判 |

第 3 条同时是**工程约束**：`max_tokens=300` 也是配合它——
如果模型想说很多，300 的预算会逼它压缩；而"暂无可追问"四个字只需要几个 token。

## 实测输出

**输入**：问题「你的数据从哪来的，为什么可信？」· 学生答「数据来自公开数据集，但和我的传感器对不上，所以只保留了能对上的字段。」

**输出**：

> 1. 公开数据集具体是哪个名称、哪个版本，如何核查？
> 2. 对不上的字段占多少比例，只保留能对上的字段会带来什么偏差？

**逐条核对**：

| 约束 | 是否守住 | 证据 |
|---|---|---|
| 1 只问空泛处 | ✅ | 两条都打在"没交代具体"和"没交代影响"上，没问无关细节 |
| 2 2 条 ≤40 字 | ✅ | 两条分别为 24 字、28 字 |
| 3 有出口 | ✅ | 本例学生确实没答完整，不该触发；机制保留 |
| 4 不评价 | ✅ | 无「回答得不错」「建议补充」等字样 |
| 5 不复述不建议 | ✅ | 没有复述原答案，没有给"你应该去补数据说明"这类建议 |

## 与规则判分的分工

这是整套设计里最关键的边界：

| | 规则判分 | AI 追问 |
|---|---|---|
| 判什么 | 命中几个要点（`hit/total`） | 没答清楚的地方在哪 |
| 依据 | 题库里写死的关键词 | 学生这次的具体措辞 |
| 输出 | 数字 + 漏掉的要点名 | 2 条问句 |
| 可否复现 | 完全可复现 | 有随机性 |
| 谁负责 | 系统 | 仅作参考，学生自己判断 |

**为什么不让模型判分**：分数不可验证，学生只会为分数辩护。
**为什么让模型追问**：判断"这句话空不空"需要语义理解，规则做不到。

分工的依据是同一句话：**判断能不能交给模型，取决于答错的代价谁承担。**
答错分数，学生会照着错分数改；问偏一个问题，学生自己能识别出来。

---

## 不起草「标准答案」的决定

预演台刻意**不用模型生成参考答案**。

理由：答辩没有标准答案，只有「你的答案站不站得住」。
模型一旦生成标准答案，学生就会背它，反而失去自己的判断。
所以这里只做两件事——**追问**和**要点覆盖核对**，
而要点是题库里写死的规则，不由模型现编。

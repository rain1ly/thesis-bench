# 答疑台 · 答复起草 Prompt

**位置**：`pages/1_答疑台.py` → `SYSTEM_PROMPT`
**参数**：`temperature=0.3`（默认）、`max_tokens=900`（默认）
**触发**：学生提交问题后自动调用；产出存入 `qa.ai_draft`，状态固定为「待审核」

---

## System Prompt（全文）

```
你是高校毕业论文指导助手，为导师起草答复草稿，不替导师做决定。

要求：
1. 直接回答学生的问题，不扩展到无关内容
2. 给可执行的具体建议，禁止「加强研究」「多读文献」这类空话
3. 涉及研究设计、数据可得性、结论可靠性的判断，明确写「这一点需要导师确认」
4. 200 字以内
5. 不代写论文正文，只给方向和方法
6. 如果给了论文题目和问题分类，回答要贴着这个题目来，不要泛泛而谈
```

## 用户消息模板

由 `build_prompt()` 拼装，**按可用信息动态增减**——这是"给模型足够上下文但不塞废话"的取舍：

```
论文题目：{thesis_title}          ← 档案里有才给（P13 新增）
学生：{student}
阶段：{开题 / 中期 / 定稿}
问题分类：{6 类之一}
问题：{学生原话}

历史相关答疑（避免重复，可在此基础上补充）：   ← 查到相似记录才给
- 问：{历史问题}
  答：{历史答复}
```

**为什么把历史答疑一起给它**：学生追问同一件事时，导师最烦的是"答复互相矛盾"。
把历史答复喂进去，模型会自动在原有基础上补充，而不是另起一套说法。

## 六条约束的来历

| # | 约束 | 对应的问题 | 类型 |
|---|---|---|---|
| 1 | 直接回答，不扩展 | 模型默认会写"这个问题很重要，需要从多个角度分析……"这类开场白，200 字预算被前戏吃掉一半 | 设计预判 |
| 2 | 禁止「加强研究」「多读文献」 | 这类话学生听了两年，等于没说。要求"可执行"是为了逼出具体动作 | 设计预判 |
| 3 | 涉及研究设计、数据、结论必须写「需要导师确认」 | **这条是硬性边界**。模型对样本量、数据可得性、结论能否成立没有判断权，但它会自信地给结论。加一句显式标记，让导师一眼看到"这里必须我自己看" | 设计预判 + 实测确认 |
| 4 | 200 字以内 | 超过 200 字导师不会读第二遍，会直接重写——草稿就白生成了 | 设计预判 |
| 5 | 不代写正文，只给方向 | 学术诚信边界。系统提供的是"怎么写"的方法，不是"写好的内容" | 硬边界 |
| 6 | 贴着论文题目回答 | **P13 之后加的**。之前没有论文题目字段，模型只能给通用建议（"你的数据要注意代表性"）。有了题目后，同样的建议可以说成"你的温室传感器数据要注意季节性偏差"——从通用变成贴题 | 实测后补 |

**第 3 条和第 6 条是这个 Prompt 里最有价值的两条**，因为它们是"通用助手"和"研究生导师助手"的分界线。

## 实测输出

**输入**：论文题目《智能温室监控系统感知层设计与数据预处理》· 陈同学 · 定稿 ·「结论部分怎么写得不像凑字数？」

**输出（134 字）**：

> 结论只回答引言提出的问题，逐条对应，不重复正文。写法：每条结论用「本文发现……」开头，后接证据（数据、案例编号），再写适用范围与限制。删掉「综上所述」「具有重要意义」等套话。若某条结论无数据支撑，删去或改为「待进一步验证」。结论是否成立、能否定稿，这一点需要导师确认。

**逐条核对**：

| 约束 | 是否守住 | 证据 |
|---|---|---|
| 1 直接回答 | ✅ | 无开场白，第一句就是方法 |
| 2 可执行 | ✅ | 给了句式模板（"本文发现……"开头）、给了删除清单（套话） |
| 3 需要导师确认 | ✅ | 末句原样出现 |
| 4 ≤200 字 | ✅ | 134 字 |
| 5 不代写 | ✅ | 给的是"怎么写结论"的方法，没有生成任何结论内容 |
| 6 贴题 | ⚠️ | 结论写法与具体题目关联度天然较低，这条在"数据来源""实验设计"类问题上体现更明显 |

最后一条标黄是如实记录：第 6 条约束不是每个分类都同样有效，
对"格式规范"类问题它几乎不起作用。这一点写在这里，比假装每条都完美更可信。

## 产出如何被约束

起草只是第一步，防线的重心在数据层：

1. 草稿写入 `ai_draft` 字段，`status` 强制为「待审核」
2. 前端展示的答复取 `answer or ai_draft` —— **导师填了 `answer`，草稿就失效**
3. 有测试锁死这个行为：`test_reviewer_answer_overrides_ai_draft`
4. AI 调用失败不影响入库：问题照常记录，只是没有草稿，导师手写

第 4 条容易被忽略：**AI 不可用不能阻塞业务**。
所以 `chat()` 返回 `(ok, text)` 而不是抛异常，失败时 `text` 就是给人看的中文原因。
